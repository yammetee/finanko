# TODO: mobile-first трекер расходов

Этот документ заменяет прежнее продуктовое направление Finanko. Цель рефакторинга — превратить приложение из финансового кабинета со счетами и портфелями в минимальный трекер фактических расходов.

## Статус реализации

Кодовая часть рефакторинга завершена 4 августа 2026 года. Неотмеченными ниже оставлены только проверки, которым нужен авторизованный доступ к реальной Supabase-сессии или ручной device/browser smoke test; они не должны выполняться агентом с production-данными без отдельного доступа и контекста выкладки.

## Целевой продукт

Основной пользовательский цикл:

```txt
Открыть приложение
  → выбрать «Чек», «Текст» или «Вручную»
  → получить или заполнить редактируемый черновик
  → сохранить расход
  → сразу увидеть обновленные сумму, аналитику и историю
```

Приложение отвечает на два основных вопроса:

- сколько потрачено за выбранный период;
- на какие категории пришлись расходы.

Плановые лимиты, прогнозы и финансовые советы в этот scope не входят.

## Правила работы анализаторов

Анализаторы предлагают данные, но не управляют сохранением:

```txt
Исходный текст/чек → анализатор → редактируемый черновик → сохранение черновика
```

- [x] Сохранить текущую реализацию распознавания чеков и покрывающие ее тесты без изменения ожидаемого поведения.
- [x] Сохранить текущую реализацию распознавания текста и fallback без исправления мелких известных ошибок.
- [x] После успешного анализа заполнять черновик суммой, валютой, категорией, описанием, датой и позициями.
- [x] Разрешить пользователю изменить любое поле черновика перед сохранением.
- [x] Сохранять фактические значения формы, а не исходный ответ анализатора.
- [x] Убрать `validateItemsMatchTotal` из блокирующего пути сохранения расхода.
- [x] Показывать `requiresReview`, `arithmetic_mismatch`, `subtotal_mismatch`, `totals_mismatch`, низкую уверенность и другие предупреждения только как информацию.
- [x] Не отключать кнопку сохранения из-за предупреждений или несовпадения общей суммы с суммой позиций.
- [x] Блокировать сохранение только при технически некорректных обязательных данных: отсутствующая/нечисловая сумма, некорректная дата, неподдерживаемая валюта или ошибка записи в базу.
- [x] При ошибке анализа сохранять исходный текст или выбранный чек в текущем состоянии UI и предлагать ручное заполнение без потери пользовательского ввода.
